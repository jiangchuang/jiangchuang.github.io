单机转集群：数据守护部署实录

高可用与集群

达梦 DM8 单机转数据守护集群手动部署文档 (完整修正版)

本文档旨在指导数据库管理员（DBA）将一个现有的、正在运行的单机达梦数据库，平滑地转换为一套双节点的数据守护（Data Watch）集群。所有配置参数均源自您提供的自动化脚本和配置文件。

1. 概述与配置总览

本次部署的目标是将一个单机数据库（IP: 172.31.3.41）作为主节点，并新增一个备用节点（IP: 172.31.3.169），形成一套主备集群。

2. 前提条件

  • 主节点 (172.31.3.41):
  • 已安装并运行一个单机达梦数据库。
  • 数据库软件版本需 小于或等于 新备库即将安装的软件版本。
  • 拥有 root 权限。
  • 备节点 (172.31.3.169):
  • 一台纯净的 Linux 服务器。
  • 拥有 root 权限。
  • 安装介质：达梦 DM8 的安装文件（如 dm8_20250825_x86_kylin10_sp1_64.iso）和许可证文件（dm.key）已准备好。
  • 网络连通性：两节点之间网络互通，并建议配置 root 用户免密 SSH。

阶段一：备节点环境准备 (在 172.31.3.169 上执行)

由于主节点环境已存在，我们只需在新备节点上准备环境。

请使用 root 用户在备节点（172.31.3.169）上执行本阶段的所有命令。

步骤 1.1: 创建用户和用户组`

为达梦数据库创建专用的运行用户和用户组。

groupadd -g 2001 dinstall
useradd -u 2001 -g dinstall -m -d /home/dmdba -s /bin/bash dmdba
echo "Dameng123" | passwd --stdin dmdba

步骤 1.2: 关闭防火墙和 SELinux

为确保集群节点间通信无阻，请关闭防火墙和 SELinux。

systemctl stop firewalld
systemctl disable firewalld
setenforce 0
sed -i.bak 's/SELINUX=enforcing/SELINUX=disabled/' /etc/selinux/config

步骤 1.3: 配置系统资源限制

为 dmdba 用户调整 ulimit 限制，防止因资源不足导致的问题。

# 将资源限制配置追加到 limits.conf 文件
cat >> /etc/security/limits.conf << EOF
dmdba soft nice 0
dmdba hard nice 0
dmdba soft as unlimited
dmdba hard as unlimited
dmdba soft fsize unlimited
dmdba hard fsize unlimited
dmdba soft nproc 65536
dmdba hard nproc 65536
dmdba soft nofile 65536
dmdba hard nofile 65536
dmdba soft core unlimited
dmdba hard core unlimited
dmdba soft data unlimited
dmdba hard data unlimited
EOF

步骤 1.4: 创建目录

创建安装、数据、归档、备份和监视器所需的目录，并设置正确的权限。

mkdir -p /home/dmdba/dmdbms /dmdata/data /dmdata/data/dmarch/DAMENG /dmdata/data/dmbak/DAMENG /dmdata/data/dmmon/DAMENG
chown -R dmdba:dinstall /home/dmdba/dmdbms /dmdata

步骤 1.5: 安装达梦软件

  1. 以 root 用户登录备节点。
  2. 挂载DM安装文件镜像文件：mount -o loop dm8_20250825_x86_kylin10_sp1_64.iso /mnt
  3. 进入存放 DMInstall.bin 和 dm.key 的mnt目录。
  4. 执行安装程序：./DMInstall.bin -i。
  5. 根据安装向导提示操作：
  • 语言：选择中文。
  • 许可证：提示时，提供 dm.key 的路径。
  • 安装类型：选择 典型安装。
  • 安装路径：设置为 /home/dmdba/dmdbms。
  • 初始化数据库：重要！ 选择 否。

阶段二：改造现有单机库为主节点 (在 172.31.3.41 上执行)

步骤 2.1: 开启归档并进行脱机备份

  1. 以 dmdba 用户连接到正在运行的单机数据库，开启归档模式。
    su - dmdba && cd /home/dmdba/dmdbms/bin
    ./disql SYSDBA/'"Dameng@123"'@localhost:5236
  1. 执行以下 SQL 开启归档。
    -- 将数据库切换到 MOUNT 状态
    ALTER DATABASE MOUNT;
    -- 开启归档模式
    ALTER DATABASE ARCHIVELOG;
    -- 添加本地归档
    ALTER DATABASE ADD ARCHIVELOG 'DEST=/dmdata/data/dmarch/DAMENG, TYPE=LOCAL, FILE_SIZE=2048, SPACE_LIMIT=102400';
    -- 重新打开数据库，让归档配置生效
    ALTER DATABASE OPEN;
    exit;
  1. 【重要】完全停止单机数据库服务，为脱机备份做准备。
    exit # 从 dmdba 用户切换回 root
    systemctl stop DmServiceDMSERVER.service # 假设原服务名为 DmServiceDMSERVER
  1. 以 dmdba 用户身份，使用 dmrman 工具对已停止的数据库进行脱机备份。
    su - dmdba && cd /home/dmdba/dmdbms/bin
    ./dmrman CTLSTMT="BACKUP DATABASE '/dmdata/data/DAMENG/dm.ini' BACKUPSET '/dmdata/data/dmbak/DAMENG/bak_for_cluster'"

步骤 2.2: 配置集群文件

此步骤在数据库服务保持停止状态下进行。以 dmdba 用户身份，创建或修改集群所需的 .ini 文件。

  1. dmmal.ini (MAL 通信配置文件)
    cat > /dmdata/data/DAMENG/dmmal.ini << EOF
    MAL_CHECK_INTERVAL = 5
    MAL_CONN_FAIL_INTERVAL = 15
    MAL_LEAK_CHECK = 1
    MAL_BUF_SIZE = 100
    MAL_SYS_BUF_SIZE = 1024
    MAL_COMPRESS_LEVEL = 0
    MAL_VPOOL_SIZE = 128
    MAL_TEMP_PATH = /dmdata/data/DAMENG/TEMP.DBF
    
    [MAL_INST1]
     MAL_INST_NAME = DB1
     MAL_HOST = 172.31.3.41
     MAL_PORT = 6236
     MAL_INST_HOST = 172.31.3.41
     MAL_INST_PORT = 5236
     MAL_INST_DW_PORT = 7236
     MAL_DW_PORT = 8236
    
    [MAL_INST2]
     MAL_INST_NAME = DB2
     MAL_HOST = 172.31.3.169
     MAL_PORT = 6236
     MAL_INST_HOST = 172.31.3.169
     MAL_INST_PORT = 5236
     MAL_INST_DW_PORT = 7236
     MAL_DW_PORT = 8236
    EOF
  1. dmarch.ini (归档配置文件)
    cat > /dmdata/data/DAMENG/dmarch.ini << EOF
    ARCH_WAIT_APPLY=0
    
    [ARCHIVE_LOCAL1]
    ARCH_TYPE = LOCAL
    ARCH_DEST = /dmdata/data/dmarch/DAMENG
    ARCH_FILE_SIZE = 2048
    ARCH_SPACE_LIMIT = 102400
    
    [ARCHIVE_REALTIME1]
    ARCH_TYPE = REALTIME
    ARCH_DEST = DB2
    EOF
  1. dmwatcher.ini (守护进程配置文件)
    cat > /dmdata/data/DAMENG/dmwatcher.ini << EOF
    [GRP1]
    DW_TYPE = GLOBAL
    DW_MODE = AUTO
    DW_ERROR_TIME = 30
    INST_RECOVER_TIME = 60
    INST_ERROR_TIME = 20
    INST_OGUID = 2507121
    INST_INI = /dmdata/data/DAMENG/dm.ini
    INST_AUTO_RESTART = 1
    INST_STARTUP_CMD = /home/dmdba/dmdbms/bin/dmserver
    RLOG_SEND_THRESHOLD = 0
    RLOG_APPLY_THRESHOLD = 0
    EOF
  1. 修改 dm.ini

编辑 /dmdata/data/DAMENG/dm.ini 文件，添加或修改以下参数：

    sed -i.bak \
        -e 's/^[ \t]*\(INSTANCE_NAME\)[ \t]*=.*$/\1 = DB1/' \
        -e 's/^[ \t]*\(ALTER_MODE_STATUS\)[ \t]*=.*$/\1 = 0/' \
        -e 's/^[ \t]*\(ENABLE_OFFLINE_TS\)[ \t]*=.*$/\1 = 2/' \
        -e 's/^[ \t]*\(MAL_INI\)[ \t]*=.*$/\1 = 1/' \
        -e 's/^[ \t]*\(ARCH_INI\)[ \t]*=.*$/\1 = 1/' \
        /dmdata/data/DAMENG/dm.ini
  1. 确保权限
    chown dmdba:dinstall /dmdata/data/DAMENG/*.ini

步骤 2.3: 重新注册服务并设置主库角色

  1. 以 root 用户重新注册服务。
    # 先卸载旧服务，确保清理干净
    /home/dmdba/dmdbms/script/root/dm_service_uninstaller.sh -n DmServiceQBQDB
    
    # 注册 dmserver 服务，注意使用 mount 模式，为后续配置做准备
    /home/dmdba/dmdbms/script/root/dm_service_installer.sh -t dmserver -p DMSERVER \
    -dm_ini /dmdata/data/DAMENG/dm.ini -m mount
    
    # 注册 dmwatcher 守护服务
    /home/dmdba/dmdbms/script/root/dm_service_installer.sh -t dmwatcher -p DMSERVER \
    -watcher_ini /dmdata/data/DAMENG/dmwatcher.ini
  1. 启动数据库服务到 MOUNT 状态。
    systemctl start DmServiceDMSERVER.service
  1. 以 dmdba 用户登录，设置 OGUID 和主库角色。
    su - dmdba
    cd /home/dmdba/dmdbms/bin 
    ./disql SYSDBA/'"Dameng@123"'@localhost:5236 << \EOF
    -- 在 disql 提示符下执行:
    SP_SET_PARA_VALUE(1, 'ALTER_MODE_STATUS', 1);
    SP_SET_OGUID(2507121);
    ALTER DATABASE PRIMARY;
    -- 根据配置文件，如果原有日志文件不足3个，需要手动添加。
    -- 如果已有3个或更多，则跳过此步。
    -- 示例：ALTER DATABASE ADD LOGFILE '/dmdata/data/DAMENG/DAMENG03.log' SIZE 2048;
    SP_SET_PARA_VALUE(1, 'ALTER_MODE_STATUS', 0);
    exit;
    EOF
  1. 【重要】保持数据库服务在 MOUNT 状态，暂时不要停止。

步骤 2.4: 传输备份到备节点

在主节点上以 root 用户身份，将备份集拷贝到备节点。

scp -r /dmdata/data/dmbak/DAMENG/bak_for_cluster root@172.31.3.169:/dmdata/data/dmbak/DAMENG/
scp -r /home/dmdba/dmdbms/bin/dm.key root@172.31.3.169:/home/dmdba/dmdbms/bin/

阶段三：配置新增备节点 (在 172.31.3.169 上执行)

步骤 3.1: 从备份恢复数据库

  1. 切换到 dmdba 用户并进入 bin 目录。
    su - dmdba
    cd /home/dmdba/dmdbms/bin
  1. 使用 dmrman 工具从备份集恢复数据库。
    # 修改备份集所属用户和组
    chown -R dmdba.dinstall /dmdata/data/dmbak/DAMENG/bak_for_cluster
    
    # 恢复数据库结构和控制文件
    ./dmrman CTLSTMT="RESTORE DATABASE to '/dmdata/data/DAMENG' FROM BACKUPSET '/dmdata/data/dmbak/DAMENG/bak_for_cluster'"
    
    # 恢复数据库
    ./dmrman CTLSTMT="RECOVER DATABASE '/dmdata/data/DAMENG/dm.ini' FROM BACKUPSET '/dmdata/data/dmbak/DAMENG/bak_for_cluster'"
    
    # 更新数据库魔数
    ./dmrman CTLSTMT="RECOVER DATABASE '/dmdata/data/DAMENG/dm.ini' UPDATE DB_MAGIC"

步骤 3.2: 拷贝和修改配置文件

  1. 在主节点上，将所有 .ini 配置文件拷贝到备节点。
   # 在主节点 (172.31.3.41) 上以 root 用户执行
   scp /dmdata/data/DAMENG/*.ini root@172.31.3.169:/dmdata/data/DAMENG/
  1. 在备节点上，以 root 用户修改 dm.ini 中的实例名。
   # 在备节点 (172.31.3.169) 上执行
   sed -i 's/INSTANCE_NAME = DB1/INSTANCE_NAME = DB2/' /dmdata/data/DAMENG/dm.ini
   chown -R dmdba:dinstall /dmdata/data/DAMENG # 确保权限正确
  1. 在备节点上，修改归档发送到DB1
       cat > /dmdata/data/DAMENG/dmarch.ini << EOF
       ARCH_WAIT_APPLY=0
   
       [ARCHIVE_LOCAL1]
       ARCH_TYPE = LOCAL
       ARCH_DEST = /dmdata/data/dmarch/DAMENG
       ARCH_FILE_SIZE = 2048
       ARCH_SPACE_LIMIT = 102400
   
       [ARCHIVE_REALTIME1]
       ARCH_TYPE = REALTIME
       ARCH_DEST = DB1
       EOF

步骤 3.3: 注册服务和配置监视器

  1. 以 root 用户注册服务。
    # 注册 dmserver 服务
    /home/dmdba/dmdbms/script/root/dm_service_installer.sh -t dmserver -p DMSERVER \
    -dm_ini /dmdata/data/DAMENG/dm.ini -m mount
    
    # 注册 dmwatcher 服务
    /home/dmdba/dmdbms/script/root/dm_service_installer.sh -t dmwatcher -p DMSERVER \
    -watcher_ini /dmdata/data/DAMENG/dmwatcher.ini
  1. 创建监视器配置文件 dmmonitor.ini。
    # 以 root 用户执行
    cat > /dmdata/data/dmmon/DAMENG/dmmonitor.ini << EOF
    MON_DW_CONFIRM = 1
    MON_LOG_PATH = /dmdata/data/dmmon/DAMENG/log
    MON_LOG_INTERVAL = 60
    MON_LOG_FILE_SIZE = 512
    MON_LOG_SPACE_LIMIT = 4096
    
    [GRP1]
    MON_INST_OGUID = 2507121
    MON_DW_IP = 172.31.3.41:8236
    MON_DW_IP = 172.31.3.169:8236
    EOF
  1. 注册监视器服务。
    /home/dmdba/dmdbms/script/root/dm_service_installer.sh -t dmmonitor -p GRP1 \
    -monitor_ini /dmdata/data/dmmon/DAMENG/dmmonitor.ini
  1. 设置监视器目录的所有权。
    chown -R dmdba:dinstall /dmdata/data/dmmon/DAMENG

步骤 3.4: 配置备库角色

  1. 启动备库服务到 MOUNT 状态。
    systemctl start DmServiceDMSERVER.service
  1. 以 dmdba 用户登录，将数据库配置为 STANDBY。
    su - dmdba
    cd /home/dmdba/dmdbms/bin
    ./disql SYSDBA/'"Dameng@123"'@localhost:5236 << \EOF
    -- 在 disql 提示符下执行:
    SP_SET_PARA_VALUE(1, 'ALTER_MODE_STATUS', 1);
    SP_SET_OGUID(2507121);
    ALTER DATABASE STANDBY;
    SP_SET_PARA_VALUE(1, 'ALTER_MODE_STATUS', 0);
    exit;
    EOF
  1. 【重要】配置完成后，保持备库服务在 MOUNT 状态，不要停止。

阶段四：启动并验证集群

步骤 4.1: 启动所有守护进程和服务

  1. 在主节点 (172.31.3.41) 上以 root 用户执行：
    # 启动守护进程，它会自动将数据库从 MOUNT 切换到 OPEN
    systemctl start DmWatcherServiceDMSERVER.service
  1. 在备节点 (172.31.3.169) 上以 root 用户执行：
    # 启动守护进程
    systemctl start DmWatcherServiceDMSERVER.service
    # 启动监视器
    systemctl start DmMonitorServiceGRP1.service

步骤 4.2: 验证集群状态

在备节点（172.31.3.169）上，使用 dmmonitor 工具查看集群状态。

su - dmdba
cd /home/dmdba/dmdbms/bin

# 新增非确认监视器配置文件备用
cat > /dmdata/data/dmmon/DAMENG/dmmonitor.ini_man << EOF
MON_DW_CONFIRM = 0
MON_LOG_PATH = /dmdata/data/dmmon/DAMENG/log
MON_LOG_INTERVAL = 60
MON_LOG_FILE_SIZE = 512
MON_LOG_SPACE_LIMIT = 4096

[GRP1]
MON_INST_OGUID = 2507121
MON_DW_IP = 172.31.3.41:8236
MON_DW_IP = 172.31.3.169:8236
EOF

./dmmonitor /dmdata/data/dmmon/DAMENG/dmmonitor.ini_man

在监视器提示符下，输入 show。您应该能看到正常的集群状态：

  • GRP1 状态为 OPEN。
  • 主库实例 (DB1) 状态为 OPEN 和 PRIMARY。
  • 备库实例 (DB2) 状态为 OPEN 和 STANDBY。
  • 归档状态（本地和远程）应为 VALID。

阶段五：安装后任务 (在主节点上执行，可能需要忽略)√

以 SYSDBA 用户连接到主节点 (172.31.3.41) 的数据库，执行 SQL 配置优化、备份和清理作业。

步骤 5.1: 运行优化配置

-- 连接到主库
-- 如果有优化参数，在这里设置，例如设置兼容模式
SP_SET_PARA_VALUE(2, 'COMPATIBLE_MODE', 4);
-- 重建统计信息
call sp_db_stat_init();

步骤 5.2: 配置备份作业

此作业配置为每周日23:00全备，周一至周六22:00增量备份。

-- 初始化作业系统
SP_INIT_JOB_SYS(1);

-- 创建周日全备作业
call SP_CREATE_JOB('FULL_BAK',1,0,'',0,0,'',0,'FULL_BAK');
call SP_JOB_CONFIG_START('FULL_BAK');
call SP_ADD_JOB_STEP('FULL_BAK', '全库备份', 6, '01020000/dmdata/data/dmbak/DAMENG/full', 1, 2, 0, 0, NULL, 0);
call SP_ADD_JOB_SCHEDULE('FULL_BAK', '每周日的23：00全库备份', 1, 2, 1, 1, 0, '23:00:00', NULL, '2021-01-01 01:00:00', NULL, '');
call SP_JOB_CONFIG_COMMIT('FULL_BAK');

-- 创建周一至周六增量备份作业
call SP_CREATE_JOB('INC_BAK',1,0,'',0,0,'',0,'INC_BAK');
call SP_JOB_CONFIG_START('INC_BAK');
call SP_ADD_JOB_STEP('INC_BAK', '增量备份', 6, '11020000/dmdata/data/dmbak/DAMENG/full|/dmdata/data/dmbak/DAMENG/inc/', 1, 2, 0, 0, NULL, 0);
call SP_ADD_JOB_SCHEDULE('INC_BAK', '周一至周六22：00增量备份', 1, 2, 1, 126, 0, '22:00:00', NULL, '2021-01-01 01:00:00', NULL, '');
call SP_JOB_CONFIG_COMMIT('INC_BAK');

步骤 5.3: 配置备份清理作业

此作业每天凌晨03:00执行，清理超过一个月的备份集。

call SP_CREATE_JOB('DB_DEL_FULL_BAK',1,0,'',0,0,'',0,'DB_DEL_FULL_BAK');
call SP_JOB_CONFIG_START('DB_DEL_FULL_BAK');
call SP_ADD_JOB_STEP('DB_DEL_FULL_BAK', '定时删除', 0, 'call SF_BAKSET_BACKUP_DIR_ADD(''DISK'', ''/dmdata/data/dmbak/DAMENG/full'');call SF_BAKSET_BACKUP_DIR_ADD(''DISK'', ''/dmdata/data/dmbak/DAMENG/inc'');SF_BAKSET_REMOVE_BATCH_S(NULL,SYSDATE-30,NULL,NULL);', 1, 2, 0, 0, NULL, 0);
call SP_ADD_JOB_SCHEDULE('DB_DEL_FULL_BAK', '每天凌晨三点执行清理1月之前备份', 1, 1, 1, 0, 0, '03:00:00', NULL, '2021-01-01 01:00:00', NULL, '');
call SP_JOB_CONFIG_COMMIT('DB_DEL_FULL_BAK');
