再谈大小写敏感设置

达梦杂谈

对于大小写敏感的设置对数据库对象名和数据的影响网上已有诸多文章详细介绍，在此不再过多赘述。本文着重想介绍的是 —— 在数据库初始化完成之后，大部分情况下当前的大小写敏感设置都能满足要求，但对于少部分需要不同于当前库大小写敏感设置的场景我们该如何实现。

库大小写敏感，需大小写不敏感

库初始化设置为大小写敏感，常见于迁移Oracle数据到达梦的场景。

场景

  • 场景1：用户表的用户名
  • 场景2：模糊搜索字段值

以上两种场景中基本都希望数据库能忽略大小写敏感

方法

有但不限于以下几种实现方式：

  • 方式1：将数据统一转换小写（或大写）后存入数据库，查询时将提供查询的值也转换为小写（或大写）。
  • 方式2：上面一种方法的变体，在需要大小写不敏感的列上创建lower(或upper)函数索引，查询时将值统一转换为小写(或大写)后进行查询。
  • 方式3：设置会话级参数case_sensitive (需对应版本支持)

实例

  • 创建测试表
create table tb_user_info
 ( 
	 id int IDENTITY(1,1),
	 username varchar(20)
 );

select case_sensitive as 当前库是否大小写敏感;
  • 方式1
  insert into TB_USER_INFO(USERNAME)values(lower('DM')); 
  insert into TB_USER_INFO(USERNAME)values(lower('dm')); 
  commit;
  
  select * from TB_USER_INFO u where u.USERNAME=lower('DM');
  select * from TB_USER_INFO u where u.USERNAME=lower('dm');
  • 方式2
  create index idx_tb_user_info_username_up on TB_USER_INFO(upper(username));
  -- 其实下面的查询不创建函数索引也可以实现忽略大小写的功能，但是基于性能考虑，一般都会考虑创建函数索引
  select * from TB_USER_INFO u where upper(u.USERNAME)=upper('dm');
  • 方式3
  ALTER SESSION SET CASE_SENSITIVE = false;
  select * from TB_USER_INFO u where u.USERNAME='dm';

技巧

假如我们希望使用数据库的唯一索引来保障用户名的唯一性该怎么办呢？我们可以考虑使用唯一函数索引来实现，如下：

-- 创建唯一索引前，请先清理重复数据(DM和dm已被识别为相同的用户名)
create unique index idx_tb_user_info_up5username on tb_user_info(upper(username));

小写不敏感，需大小写敏感

库初始化设置为大小写不敏感，常见于迁移MySQL或SQL Server数据到达梦的场景。

场景

略

方法

有但不限于以下几种实现方式：

  • 方法1：在程序中使用md5等函数对需要忽略大小写的字段进行hash运算后存入单独的列，查询时同样先在程序中对提供查询的值先进行hash运算后再查询单独的列
  • 方法2：设置会话级参数case_sensitive (需对应版本支持)

实例

  • 创建测试表
create table tb_user_info
 ( 
	 id int IDENTITY(1,1),
	 username varchar(20)
 );

select case_sensitive as 当前库是否大小写敏感;
  • 方式1
  alter table tb_user_info ADD md5username VARBINARY(16);
  -- 程序中计算分别计算出'DM'和'dm'的散列值(如MD5）后，将该计算后的值写入md5username列，如下
  insert into TB_USER_INFO(USERNAME,MD5USERNAME)values('DM',0x2ECDA7A0252B442AC6ECF47462119F51); 
  insert into TB_USER_INFO(USERNAME,MD5USERNAME)values('dm',0x608E7DC116DE7157306012B4F0BE82AC); 
  commit;
  
  -- 查询时，程序将要搜索的值使用相同的散列函数（如MD5）计算后，在新加的列上进行查询
  select * from TB_USER_INFO u where u.MD5USERNAME=0x2ECDA7A0252B442AC6ECF47462119F51;
  select * from TB_USER_INFO u where u.MD5USERNAME=0x608E7DC116DE7157306012B4F0BE82AC;
  • 方式2
  ALTER SESSION SET CASE_SENSITIVE = false;
  select * from TB_USER_INFO u where u.USERNAME='dm';
