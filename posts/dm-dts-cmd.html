基于 DTS 命令行的定时数据迁移

迁移与同步

摘要:

本文档旨在指导用户如何在Linux环境下，利用达梦数据库的命令行工具dts_cmd_run.sh实现自动化数据迁移。我们将通过一个简单的“达梦到-达梦”同步场景，完整地展示从使用图形化工具生成配置文件，到部署、测试，再到最终配置cron定时任务的全过程。

1. 核心流程概述

  1. 准备配置文件：在任何有图形化界面的电脑上，使用DTS工具的向导模式，轻松生成一个.xml格式的迁移任务配置文件。
  2. 部署与测试：将.xml文件上传到目标Linux服务器，并使用dts_cmd_run.sh命令手动执行一次，以验证配置的正确性和连通性。
  3. 设置定时任务：利用Linux的cron服务，让这个迁移任务在无人值守的情况下，每天在指定时间自动运行。

2. 环境与配置示例

角色IP地址端口模式名 (Schema)待迁移的表
源端10.0.0.15236SRC_SCHEMATEST_TABLE
目的端10.0.0.25236DEST_SCHEMATEST_TABLE

3. 实施步骤

步骤一：使用图形化DTS生成配置文件

提示： 这一步建议在您本地的Windows或带有图形界面的Linux机器上完成，因为图形化向导可以极大地简化配置过程。

  1. 启动DTS工具：
  • 在达梦安装目录的 tool 文件夹下，执行 dts.sh (Linux) 或 dts.exe (Windows)。
  1. 新建工程:
  • 在左侧“迁移管理”区域右键，选择“新建工程”。
  • 工程名填写“SimpleSync”，点击“确定”。
  1. 新建迁移任务:
  • 在刚创建的“SimpleSync”工程下的“迁移”项上右键，选择“新建迁移”。
  • 迁移名称同样填写“SimpleSync”，点击“确定”。
  1. 配置迁移向导:
  • 迁移方式选择: 在向导第一步，选择 DM -> DM，点击“下一步”（也可根据用户源端实际使用的数据库进行选择）。
  • 源端配置:
  • 输入源端数据库的IP 10.0.0.1、端口 5236。
  • 输入可以访问源端模式的用户名（如SRC_USER）及密码。
  • 点击“下一步”。
  • 目的端配置:
  • 输入目的端数据库的IP 10.0.0.2、端口 5236。
  • 输入可以访问目的端模式的用户名（如DEST_USER）及密码。
  • 点击“下一步”。
  • 迁移选项: 保持默认设置，点击“下一步”。
  • 选择迁移对象:
  • 在模式列表中，源模式选择 SRC_SCHEMA，目的模式选择 DEST_SCHEMA。
  • 在右侧的迁移对象类型中，确保“表(Table)”已被勾选。
  • 点击“下一步”。
  • 筛选具体表对象:
  • DTS会列出 SRC_SCHEMA 模式下的所有对象。使用查找功能或手动找到 TEST_TABLE 表，并勾选它。
  • （可选）如果需要修改迁移策略（如数据存在时是覆盖还是忽略），可以选中表后点击“转换”按钮进行设置。对于全量同步，通常默认即可。
  • 点击“下一步”。
  1. 导出配置文件:
  • 在迁移向导的最后一步，不要点击“完成”或“立即执行”。
  • 点击界面左下角的“源代码”按钮。
  • 此时会弹出一个窗口，显示本次迁移任务的 XML 格式源代码。
  • 全选（Ctrl+A）并复制（Ctrl+C）这些XML内容，将其粘贴到一个新建的文本文件中，并命名为 sync_job.xml。

至此，我们已经成功获取了核心的配置文件，后续操作将在Linux服务器上进行。

步骤二：在Linux服务器上部署并手动测试

1. 创建工作目录并上传文件

最佳实践：我们将在 /data 目录下创建一个专门的文件夹来存放所有DTS任务相关的文件。/data 目录通常用于存放应用数据，非常适合此场景。

  • 以 root 用户或有 sudo 权限的用户，执行以下命令：
    # 创建DTS任务的主目录
    sudo mkdir -p /data/dts_jobs
    # 将此目录的所有权赋予dmdba用户，以便其可以读写
    sudo chown -R dmdba:dinstall /data/dts_jobs
  • 以 dmdba 用户登录，并使用scp或sftp等工具，将之前准备好的 sync_job.xml 文件上传到 /data/dts_jobs/ 目录中。

2. 手动执行迁移测试

我们的目标是展示dts_cmd_run.sh最直接、最简化的使用方式。下面的命令没有使用任何变量，所有路径和参数都清晰可见。

  • 以 dmdba 用户，在终端中执行以下命令：
    /home/dmdba/dmdbms/tool/dts_cmd_run.sh config \
    file=/data/dts_jobs/sync_job.xml \
    report=/data/dts_jobs \
    log=/data/dts_jobs \
    err_log=/data/dts_jobs
  • 命令解读：
  • /home/dmdba/dmdbms/tool/dts_cmd_run.sh: 这是DTS命令行工具的绝对路径。
  • config: 告诉程序我们要通过参数来配置任务。
  • file=/data/dts_jobs/sync_job.xml: 指定配置文件。这是最重要的参数。
  • report=/data/dts_jobs: 指定报告（.xlsx格式）的输出目录。
  • log=/data/dts_jobs: 指定日志（.txt格式）的输出目录。
  • err_log=/data/dts_jobs: 指定错误日志的输出目录。

3. 验证结果

  • 观察终端输出：如果命令执行后，屏幕上显示 "run finish!"，则表示迁移任务已成功执行。
  • 检查生成的文件：执行 ls -l /data/dts_jobs，你会看到新生成的、带有时间戳的报告和日志文件，如 transform_report_xxxx.xlsx。
  • 核对数据库数据：登录到目的端数据库 (10.0.0.2)，执行SQL查询 SELECT * FROM DEST_SCHEMA.TEST_TABLE;，确认数据已按预期同步过来。
步骤三：配置Crontab实现定时调度

1. Crontab简介

crontab 是Linux系统下的一个强大的定时任务工具。你可以用它来安排任何命令或脚本在指定的时间（例如每天、每周、每小时）自动运行。每个用户都可以拥有自己的 crontab 任务列表，任务会以该用户的身份执行。

2. 编辑定时任务

  • 以 dmdba 用户登录（当然您也可以使用其他操作系统用户），因为我们需要以这个用户的身份来运行DTS任务。
  • 在终端输入以下命令来编辑当前用户的定时任务：
    crontab -e

（第一次使用时，系统可能会让你选择一个文本编辑器，如 nano 或 vim，选择你熟悉的即可。）

3. 添加定时任务

  • 在打开的编辑器中，移动到文件末尾，添加下面这行内容：
    # 每天凌晨2点，执行达梦DTS数据同步任务
    0 2 * * * /home/dmdba/dmdbms/tool/dts_cmd_run.sh config file=/data/dts_jobs/sync_job.xml report=/data/dts_jobs log=/data/dts_jobs err_log=/data/dts_jobs > /dev/null 2>&1
  • 这一行配置的含义：
  • 0 2 * * *: 这是cron的时间表达式，格式为 分 时 日 月 周。
  • 0: 第0分钟。
  • 2: 凌晨2点。
  • *: 每一天。
  • *: 每一个月。
  • *: 每周的每一天。
  • 合起来就是：每天的凌晨2点0分执行任务。
  • /home/dmdba/dmdbms/tool/dts_cmd_run.sh ...: 这就是我们步骤二中手动测试成功的那条完整命令。
  • > /dev/null 2>&1: 这是一个常用技巧，意思是将命令执行过程中所有的屏幕输出（包括正常信息和错误信息）都丢弃掉，不保存。这样可以保持系统干净，避免 cron 发送不必要的通知邮件。我们需要的日志，DTS工具自己会生成到 /data/dts_jobs 目录中。

4. 保存并验证

  • 保存并退出编辑器（在vim中是按ESC后输入:wq，在nano中是按Ctrl+X后按Y）。
  • 系统会自动提示 "crontab: installing new crontab"。
  • 你可以随时使用 crontab -l 命令来查看当前已配置好的定时任务列表，确认我们的任务已在其中。

至此，您的DTS数据迁移任务就已经配置完成，并会在每天凌晨2点准时自动执行，实现了真正的自动化。
